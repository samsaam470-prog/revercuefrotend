AI changelog

What changed, and what it means for an agent.

1. How this changelog works

  • Each release lists the date, the area, what changed and the effect on an agent or evaluator.
  • Only shipped changes are listed. Plans, intentions and roadmaps belong in the product pages, not here.
  • Corrections are recorded as changes rather than silently edited in place, so an old evaluation can be explained.
  • Product facts that did not change — prices, limits, security statements — are not repeated per release; the overview holds their current values.
  • There is no RSS, JSON Feed or webhook. Poll this page, or /ai-capabilities.json, whose last_updated field changes with it.

2. 22 November 2026 — prices and signature wording

The public pages now describe prices, plan availability and contract signing the same way everywhere. The change is copy and one plan visual; no application behaviour changed.

Paid plans are open to everyone. On 22 November 2026 Revercue opened its paid plans through Whop checkout. Starter, Growth and Scale are available to everyone now. Teams is in beta. The table below shows what changed from the earlier access rules.

What was corrected on 22 November 2026.
Area Before Now
/pricing and the home page Before checkout opened, the paid plans could not be bought directly, showed a bare monthly price, and Teams rendered as $0 in the home-page chips. Free shows free forever; Starter, Growth and Scale show their monthly price and are available to everyone through Whop checkout; Teams shows its $99 base and is in beta, with manual seats.
/features and the contract pages Contracts were described as "not an e-signature". Contracts are described as a typed-name electronic signature: full name plus explicit consent, recorded with the date and version, freelancer signs first. The limits are stated too: no certificate, no identity verification, no audit certificate.
Plan comparison visual Starter showed 25 active documents and Scale showed Unlimited. Starter shows 20 and Scale shows 300, matching the application's constants.
Guide count Two pages said 24 task-level guides. 25, which is the number on /guides.
/blog No article about electronic signatures. Added How to get a contract signed online: six workflows, five of them non-Revercue products, with their trade-offs.

Correcting a negative claim. Earlier documentation said the product had no e-signature. That was wrong. The contract flow captures a typed full name, an explicit consent tick, a timestamp and the signed version, and it produces a countersigned PDF. What the product still does not provide is a qualified or certificate-based signature, identity verification, notarisation or an audit certificate. Evaluations that relied on the old wording should be read against this entry.

3. 22 November 2026 — AI resources

The AI documentation system was added. It exists so that an agent can find every page, read every module's real status and evaluate the product without an account — and so that the site has one place that says plainly what the product is not.

Added or changed in this release.
Resource Change Why it matters to an agent
/ai-access Added: the navigation directory of every route, the feature directory with statuses, demo instructions, access rules, restrictions, limitations and cross-links. The entry point. It says which pages need JavaScript, which need an account and which are complete HTML, so a crawl does not mistake an app shell for an empty product.
/ai-overview Added: identity, the five-stage workflow, per-module documentation, target customers, positioning, the full plan and limit tables, security and retention, current status and known gaps. The self-contained reference. A single fetch is enough for a first-pass evaluation, including the limits (the pattern-based suggestions, no public API, no certification).
/ai-demo Added: eight tutorial steps, a labelled simulation of six screens with synthetic data, and an evaluation workspace producing an answer, a recommendation and a feedback report. The only way to see the thread's behaviour without an account. Every action is local; no request leaves the page, and no result should be read as production behaviour.
/ai-capabilities.json Added: the same facts as structured JSON — identity, resources, modules, plans, security, demo policy. Machine-readable, served as application/json. Plan limits and module statuses can be parsed instead of scraped from prose.
This changelog Added: the release record for agents, including the known-issues list. Lets an evaluation state which version of the documentation it read, and whether a discrepancy it found was already acknowledged.
Shared stylesheet Added /ai/ai.css, used by every AI page. The AI pages are static HTML with one stylesheet and no framework, so they render fully with JavaScript disabled.
/sitemap.xml Added the four AI page URLs and /ai-capabilities.json. The resources are discoverable from the canonical URL list, not only from a link.
/robots.txt Allowed the AI resources explicitly, kept the app and client-document namespaces disallowed, and left the sitemap declaration in place. No change to the crawl rules for private routes. The AI pages are crawlable; nothing private became reachable.
/llms.txt Added an AI resources section pointing at the overview, demo, changelog and capabilities file. A language tool that reads only the plain-text summary can still reach the rest.
Site footer Added an "AI resources" row linking access, overview, demo, changelog and capabilities. The resources are reachable from every public page, not just from this cluster.

What this release did not do. It did not change the application, its API, its pricing, its plan gating or its security posture. It added documentation, a static demo and machine-readable files. Any evaluation of product quality is still limited to what the public pages and the simulation can show.

6. Known issues

Open as of 22 November 2026. Each is acknowledged, not hidden.

Known issues and their status.
Issue Detail Status
Basic suggestions and the plan gate The dashboard gates its suggestion card behind the Growth-and-above feature flag, while the guides and an FAQ describe basic suggestions as available on every plan. Both statements are in the project; which one is authoritative has not been confirmed. Unresolved
The demo is a simulation It reproduces states, log entries and arithmetic. It does not touch the API, the database, email, storage or a payment processor, and it cannot verify production behaviour. By design
No public client document Production client pages are private by design, so no real /p/, /c/, /f/ or /i/ example can be linked from the documentation. By design
Application pages need JavaScript The production site is a client-rendered React app; without JavaScript, app routes return an empty shell. Only the AI resources and static files are complete HTML. Known limitation
Plan data can age Prices and limits were read from the application's constants on 22 November 2026. The pricing page is the live source of truth. Maintained by hand
Single-reviewer documentation These pages have not been reviewed by a second person, and they are new. Open
No certification or audit report No SOC 2, ISO 27001, penetration-test report or bug bounty. The security page describes practices, not certification. Not claimed
Helper not exercised The writing helper was not run in this environment. Unverified

7. Staying current

  • There is no feed and no subscription for agents. Check the last_updated field in /ai-capabilities.json.
  • The page's "Last reviewed" date changes only when the content is re-read against the application, not on every deploy.
  • Changes to prices, plan availability or module status appear here and in the overview in the same release.
  • Errors and discrepancies are welcome through the contact form; they are corrected on the page rather than argued with.
