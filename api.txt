# REVERCUE — API CONTRACT
# File: api.txt
# Purpose: Every endpoint the frontend calls. The request body, the response shape, the error codes.
# Audience: The AI building the frontend. It must not invent endpoints. Every function in src/api/ maps to a route here.
# Base URL: https://revercue-api.samsaam470.workers.dev
# Auth: Authorization: Bearer <user_jwt> for user routes; Bearer <admin_jwt> for admin routes; none for public routes.
# Content-Type: application/json for all requests and responses, except file uploads (multipart/form-data) and CSV/PDF downloads.
# Error shape (every error): { "error": "error_code", "message": "Human-readable message.", "details": {} }
# Error codes: invalid_payload, unauthorized, forbidden, not_found, conflict, rate_limited, plan_limit_reached, config_error, internal_server_error.
# Status codes: 200 ok, 201 created, 400 validation, 401 auth, 403 forbidden/plan, 404 not found, 409 conflict, 429 rate limit, 500 server.
# Pagination: ?page=1&limit=50 -> response includes { data: [], pagination: { page, limit, total, total_pages } }.
# Timestamps: ISO 8601 strings.

# ============================================================
# PART 1 — AUTH (/api/auth)
# ============================================================

## POST /api/auth/signup
Body: { email, password, tos_accepted: true, newsletter_opt_in: boolean }
Response 201: { success: true, token: "pre-auth-jwt", user: { id, email, plan: "free", onboarding_step: 1, email_verified: false } }
Errors: 400 invalid_payload (email, password < 8, tos not true), 409 conflict (email exists), 429 rate_limited.
Side effects: creates the user in Turso (bcrypt hash), stores the OTP (hashed, 5-min expiry), sends the OTP via FormSubmit to the user's email (first send triggers the activation email).

## POST /api/auth/login
Body: { email, password }
Response 200: { success: true, token, user: { id, email, plan, onboarding_step, two_factor_enabled } } OR { success: true, requires_2fa: true, pre_2fa_token }
Errors: 400 invalid_payload, 401 invalid_credentials, 429 rate_limited (5 attempts / 15 min).
Side effects: creates a session row, updates last_login_at. If 2FA is on, sends the 2FA OTP via FormSubmit and returns the pre_2fa_token (no full token yet).

## POST /api/auth/google
Body: { id_token }
Response 200: same shape as login.
Errors: 400 invalid_payload, 401 invalid_google_token.
Side effects: if the user is new, creates the account (onboarding_step 1) and sends a welcome email via FormSubmit.

## POST /api/auth/verify-email
Headers: Authorization: Bearer <pre-auth-jwt>
Body: { code: "6 digits" }
Response 200: { success: true, email_verified: true, token: "full-jwt" }
Errors: 400 invalid_code (with attempts_remaining), 400 code_expired, 429 too_many_attempts, 401 unauthorized.
Side effects: sets email_verified = 1, deletes the OTP row.

## POST /api/auth/resend-verification
Headers: Authorization: Bearer <pre-auth-jwt>
Response 200: { success: true, cooldown_seconds: 90 }
Errors: 429 cooldown_active (with retry_after), 429 rate_limited.
Side effects: generates a new OTP, sends it via FormSubmit.

## POST /api/auth/2fa/verify
Body: { code: "6 digits", pre_2fa_token }
Response 200: { success: true, token, user }
Errors: 400 invalid_code (with attempts_remaining), 400 code_expired, 429 too_many_attempts, 401 unauthorized.
Side effects: creates a session row, updates last_login_at.

## POST /api/auth/2fa/resend
Body: { pre_2fa_token }
Response 200: { success: true, cooldown_seconds: 90 }
Errors: 429 cooldown_active, 401 unauthorized.

## POST /api/auth/password-reset/request
Body: { email }
Response 200: { success: true } (always, even if the email does not exist — no leak)
Side effects: if the email exists, sends a reset OTP via FormSubmit.

## POST /api/auth/password-reset/verify
Body: { email, code, new_password }
Response 200: { success: true }
Errors: 400 invalid_payload, 400 invalid_code, 400 code_expired, 429 too_many_attempts.
Side effects: updates the password hash (bcrypt), revokes all sessions.

## GET /api/auth/me
Headers: Authorization: Bearer <user-jwt>
Response 200: { user: { id, email, name, plan, onboarding_step, formsubmit_activated, tutorial_completed, email_verified, two_factor_enabled } }
Errors: 401 unauthorized.

## POST /api/auth/logout
Headers: Authorization: Bearer <user-jwt>
Response 200: { success: true }
Side effects: revokes the current session (sets revoked_at).

## GET /api/dashboard/summary
Response 200: { active_documents, clients, follow_ups_due, revenue_this_month, pending_total, pending_count, unread_notifications }

# PART 4 — PROPOSALS (/api/proposals)
# ============================================================

All routes require the user JWT.

## GET /api/proposals?status=&page=&limit=
Response 200: { data: [ { id, title, client_id, status, public_id, total_time_spent_seconds, created_at } ], pagination: {...} }

## POST /api/proposals/draft
Body: { client_id? OR client_name + client_email, title, problem, sections: [], currency, timeline_length, tone }
Response 201: { success: true, id, status: "draft", client_id }
Errors: 400 invalid_payload, 403 plan_limit_reached (active-document limit).

## GET /api/proposals/:id
Response 200: { proposal: { ...all fields } }
Errors: 404 not_found.

## PATCH /api/proposals/:id
Body: { title, content: {...}, currency, expiry_date, brand_primary, brand_secondary, allow_pdf_download }
Response 200: { success: true, updated_at }
Errors: 404 not_found.

## POST /api/proposals/:id/publish
Response 200: { success: true, public_id, url }
Errors: 403 plan_limit_reached, 404 not_found.
Side effects: sets status = published, generates public_id, creates a notification.

## POST /api/proposals/:id/duplicate
Body: { client_id? }
Response 201: { success: true, id, status: "draft" }
Errors: 403 plan_limit_reached, 404 not_found.

## POST /api/proposals/:id/archive
Response 200: { success: true, status: "archived", archive_deletion_date }
Errors: 403 archive_limit_reached, 404 not_found.

## POST /api/proposals/:id/unarchive
Response 200: { success: true, status: "published" }
Errors: 404 not_found.

## POST /api/proposals/:id/share
Body: { channel }
Response 200: { success: true }
Side effects: creates a communication_log entry (document_shared). The user sends the link themselves.

## POST /api/proposals/:id/password
Body: { password } OR { remove: true }
Response 200: { success: true, password_protected: true/false, count: "3 of 15 used" }
Errors: 403 forbidden (plan does not allow), 403 plan_limit_reached (count full), 400 invalid_payload (password < 6).

## POST /api/proposals/:id/autosave?token=<jwt>
Body: { content: {...} }
Response 200: { success: true }
(The sendBeacon route; the token is in the query string because sendBeacon cannot set headers.)

## DELETE /api/proposals/:id
Response 200: { success: true }
Side effects: deletes the proposal; the B2 files and the PDF email are handled by the backend.

# PART 14 — THE RATE LIMITS
# ============================================================

Signup: 5 / hour / IP.
Login: 5 / 15 min / IP.
OTP resend: 1 / 90 sec / user, 5 / hour / user.
2FA verify: 3 attempts / code.
Password reset: 3 / hour / email.
Change password: 3 / hour / user.
Public document open: 100 / hour / IP.
File upload: 20 / hour / user.
Admin login: 5 / 15 min / IP.
General API: 300 / min / user.
