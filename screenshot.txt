# REVERCUE — SCREENSHOT CAPTURE GUIDE
# File: screenshot.txt
# Purpose: How to capture the 12 real product screenshots, where to save them, and where they appear in the public site.
# Audience: The AI (or the developer) after building the dashboard and the builders. This is the LAST step, because the screenshots need the built product.
# The public site uses REAL screenshots, not stock photos, not abstract illustrations. The product sells itself by showing itself.

# ============================================================
# PART 1 — THE RULES (before any capture)
# ============================================================

1. Real product, real data. Use a sample freelancer "Acme Studio" (a serif wordmark, a warm palette). Sample clients "Acme Co.", "Beta Ltd.", "Gamma Inc." Sample amounts ($500, $1,200, $2,500). Never lorem ipsum, never "John Doe."
2. The real brand. On the client-facing pages (proposal, contract, invoice, form), the screenshots show the FREELANCER's brand (Acme Studio), not "Revercue". On the dashboard screenshots, show the Revercue shell (gold accent, dark palette).
3. The state matters. Capture the screen in a REALISTIC state: the stat strip with numbers, the suggestion card with a real suggestion, the activity feed with real events. Not an empty state (unless the empty state is the point).
4. The crop. 16:10 for the hero and the feature sections. 4:3 for the cards. Captured at 2x (retina), exported at 1x and 2x.
5. The gold-glow treatment. Every screenshot sits in a card (bg var(--bg-card), 1px border, 12px radius) with a gold glow behind (0 40px 120px rgba(201,169,97,0.15)). On the Home hero: 2deg rotation. Everywhere else: straight.
6. The alt text. Every screenshot has alt text that describes what it shows, not "screenshot". E.g., "The Revercue dashboard with the stat strip, suggested actions, and recent activity."

# ============================================================
# PART 3 — THE CAPTURE PROCESS (for the AI)
# ============================================================

After building the dashboard and the builders:
1. Seed the sample data (Acme Studio, Acme Co., Beta Ltd., Gamma Inc., the documents, the communication entries, the expenses). A dev-only seed script (not shipped).
2. Start the dev server (npm run dev).
3. Log in as the sample freelancer.
4. For each screenshot:
   a. Navigate to the route.
   b. Set the data to the realistic state (Part 2).
   c. Open the browser's screenshot tool (or a tool like Playwright/Puppeteer at 2x device pixel ratio).
   d. Capture the screen (the full page or the specified crop).
   e. Save to public/screenshots/ with the specified name (1x and @2x).
5. Replace the placeholders in the public site: the Home hero, the thread section, the client-view section, the Features sections, the Pricing table, the Security page, the Sign Up page.
6. Verify the images load (the correct path, the correct alt text, the gold-glow treatment).
7. Remove the sample data seed from the production build (it is dev-only).

# ============================================================
# PART 4 — THE PLACEHOLDERS (before the screenshots exist)
# ============================================================

Before the real screenshots are captured, the public site uses placeholders:
  A grey box (bg var(--bg-elevated)) with the correct aspect ratio (16:10 or 4:3).
  A caption in the center: "Screenshot: [the screen name]" (e.g., "Screenshot: Dashboard Overview").
  The alt text is the final alt text (so the SEO is correct from day one).
The placeholders are replaced in the last step (after the screenshots are captured). The site is functional with placeholders; the real screenshots are the final polish.

# ============================================================
# PART 5 — THE DESIGN RULES FOR THE SCREENSHOTS
# ============================================================

The screenshots are the product's face. They must look like the product, not a mockup.
No stock photos. No abstract illustrations. No "happy people at a laptop."
The client-facing screenshots show the freelancer's brand (Acme Studio), not Revercue's. This is the white-label proof.
The dashboard screenshots show the Revercue shell (gold accent, dark palette). This is the product's face.
The gold-glow treatment is consistent. The hero is rotated (2deg); the rest are straight.
The alt text describes what the screenshot shows, not "screenshot."
The crop is consistent: 16:10 for the hero and features, 4:3 for the cards.
The data is realistic: real names, real amounts, real statuses. Never lorem ipsum.
The empty states are not the screenshots (unless the point is the empty state). The screenshots show the product in use.
